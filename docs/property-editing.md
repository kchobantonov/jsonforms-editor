# Property editing

The inspector is generated by `inspectorDefinition` as JSON Schema and a JSON Forms UI schema. Field titles and description annotations are translated through the editor message catalog. Descriptions stay visible beside the inputs so focusing or blurring a control does not shift other click targets. English and Bulgarian are included, and hosts can override messages.

| Category     | Contents                                                                                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| General      | UI label/text, action, image information, spacer height, horizontal/vertical layout type                                                                                                                                   |
| Field        | Data type (including unions), schema title, description, default value                                                                                                                                                     |
| Validation   | Required, string length/pattern/format, inclusive/exclusive numeric bounds and multiples, array size/uniqueness, object property counts, constant and allowed values                                                       |
| Choices      | Enum/oneOf choice rows, display titles and selection widget                                                                                                                                                                |
| Advanced     | Examples, read/write-only annotations, deprecation, references/comments, properties and dependencies, array item/tuple/contains schemas, composition and conditional schemas, reusable definitions and content annotations |
| Appearance   | UI read-only and multiline display                                                                                                                                                                                         |
| Layout       | Horizontal column allocation and group collapse options                                                                                                                                                                    |
| Translations | Translation key and language-specific labels/descriptions                                                                                                                                                                  |
| Rules        | Conditional visibility and enabled state                                                                                                                                                                                   |

Applicable validation fields are combined for union types. Modern keywords are offered for the document's declared dialect; already-authored keywords remain editable. Unknown schema extensions are preserved. Resource identifiers, dialect changes, anchors, boolean schemas and custom keywords remain available in JSON Model.

Complex values use JSON editors so null, booleans, numbers, arrays and objects retain their actual types. Apply validates the JSON and keyword shape; a blank value removes the keyword. A default is a schema annotation, not a mutation of sample data. Advanced schema edits do not fetch remote references. Structural property deletion should use the schema tree to perform connected-data cleanup.

Components and Schema remain visible in separate resizable panes. Both have search. Schema search retains ancestors and expands matching paths; clearing search restores the user's expansion state. Type icons and required markers come from the schema. Rename is inline (Enter or Save; Escape cancels). Whole palette rows are drag sources and do not add on click. In the schema tree the name/icon region is the drag source, leaving tree and action buttons available. Canvas handles separate dragging from interactive form previews. The library also supplies keyboard drag support.

Horizontal layout children can be resized from their trailing edge. Resizing snaps to the existing 16-column grid (2–16), previews on the canvas, and commits one history entry on release. Escape, pointer cancellation, or losing window focus cancels the preview. Arrow keys adjust by one column; Home and End select the minimum and maximum. The Columns property reflects the committed width; Auto remains available in the property panel.

Deleting a property or definition is an undoable document transaction. It removes dependent named local-reference schemas, connected controls, rules using removed fields, required/dependency entries and sample data (including object-array entries). Registered UI schemas are cleaned as well. Embedded resource identifiers and references without an owning named field require JSON Model editing because their resolution scope cannot be safely inferred by the local pointer editor. External references are not fetched or modified.

“Show unused fields only” includes fields rendered by an object control's generated detail layout, including a control bound to `#`. With an explicit `options.detail` UI schema, only its included controls (and their generated object descendants) count as used; omitted fields remain available in the tree.

Array fields expose **Items type** in the Field section to edit `items.type`, including union types. Other item keywords are preserved. Boolean item schemas and legacy tuple arrays remain editable through Advanced's Items JSON editor.
